# 14. AI-ассистент

Вкладка «AI-ассистент». Модель работает **локально** через [Ollama](https://ollama.com) — данные магазина никуда
не отправляются. Код:

| Модуль | Роль |
|---|---|
| `scripts/ai_chat.py` | Клиент Ollama, системный промпт, инструменты (`Tools`), разбор ответа модели |
| `scripts/agent_workflows.py` | Распознавание типовых сценариев (годовой отчёт по артикулам, топы, месяц, артикул) и детерминированные шаги |
| `scripts/analytics_models.py` | Датаклассы состояния (`WorkflowState`, агрегаты по артикулу) |
| `scripts/analytics_reducers.py` | Сжатие результатов инструментов для модели, годовые сводки |
| `scripts/payload_policy.py` | Какой вид данных отдать модели на каждом шаге |
| `scripts/ai_interpreter.py` | Старый модуль интерпретации; **не используется** |

Настройки: `OLLAMA_HOST` (по умолчанию `http://localhost:11434`), `OLLAMA_MODEL` (по умолчанию `qwen3:4b`).
Модель можно сменить в интерфейсе; список — `GET /api/tags`. Проверка доступности — `check_ollama_model`.

## Протокол с моделью

Системный промпт (`SYSTEM_PROMPT`) требует от модели **ровно один JSON-объект** одного из двух видов:

```json
{"type": "DATA_REQUEST", "needs": [{"tool": "get_month_summary", "args": {"period": "2026-03"}}], "reason": "..."}
{"type": "FINAL_ANSWER", "answer": "ответ на русском"}
```

`parse_ai_response` терпим к отклонениям (лишний текст, другие названия полей) и нормализует ответ.
Промпт содержит текущую дату и год — «этот год» модель понимает правильно.

## Инструменты — `Tools`

Работают **только с локальными файлами** (в Ozon не ходят):

| Инструмент | Данные |
|---|---|
| `list_reports` | Какие месячные отчёты есть в `reports/` |
| `get_month_summary(period)` | Блок показателей P/Q месяца ([04](04-monthly-report.md#4-блок-показателей-колонки-pq)) |
| `get_month_report_full_data(period)` | Все строки листа «Заказы», статистика по артикулам |
| `get_top_profit`, `get_top_orders(period, n)` | Топ артикулов по прибыли / заказам |
| `get_artikul_stats(period, artikul)`, `search_artikul(query)` | Один артикул, поиск |
| `get_costs_columns`, `get_artikul_cost`, `get_costs_bulk` | `costs.xlsx` |
| `get_abcxyz_summary(period)` | Сводка ABC/XYZ-отчёта |
| `get_artikul_abcxyz`, `get_category_list` | В разработке, могут вернуть ошибку |

Период принимается как `"2026-03"` или `"Март 2026"`.

## Цикл ответа (`app_flet.py`, обработчик отправки, ~строка 2107)

До 4 шагов в фоновом потоке:

1. `build_workflow_state` распознаёт сценарий. Если для него известны следующие данные
   (`get_workflow_followup_needs`, например «годовой отчёт» → сначала `list_reports`, затем
   `get_month_report_full_data` за каждый **существующий** месяц), инструменты вызываются **без модели**.
2. Иначе модель получает вопрос, последние 6 сообщений истории, контекст сессии (выбранный период и артикул) и блок
   данных (`format_tool_results` → сжатие через `payload_policy`/`analytics_reducers`). Температура 0,7 без данных
   и 0,2 с данными. Ответ стримится; «размышления» модели показываются отдельно.
3. `DATA_REQUEST` → `execute_tools` → результаты копятся и идут на следующий шаг. `FINAL_ANSWER` → ответ.
4. Если шаги кончились, а ответа нет, — запасной ответ по собранным данным (`build_workflow_fallback_answer`),
   иначе сообщение «Модель не завершила анализ».

Отмена: запрос помечается отменённым, все его события в очереди интерфейса отбрасываются (поток Python при этом
доживает до конца текущего шага).

Debug-режим (меню «Инструменты») пишет в журнал каждый шаг: сырой ответ модели, разобранный JSON, вызовы
инструментов и их результаты. Журнал открывается по F2.

## Ограничения

- Качество зависит от модели: `qwen3:4b` небольшая и иногда отвечает не по протоколу — для этого и нужны
  детерминированные сценарии и терпимый разбор.
- Ассистент видит только то, что уже сохранено в отчётах. Свежие данные Ozon — после формирования отчёта.

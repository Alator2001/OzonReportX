# 14. AI-ассистент

Вкладка «AI-ассистент». Модель работает **локально** через [Ollama](https://ollama.com): данные магазина
в модель за пределы компьютера не уходят. Ассистент видит все данные программы через инструменты и сам решает,
что запросить. Код:

| Модуль | Роль |
|---|---|
| `scripts/ai_chat.py` | Клиент Ollama: настройки, возможности модели (`model_capabilities`, `check_ollama_model`), один потоковый запрос `chat` |
| `scripts/ai_agent.py` | Агентный цикл: системный промпт, вызовы инструментов, бюджет контекста, повторы |
| `scripts/ai_tools.py` | Инструменты для модели поверх базы и живого Ozon (только чтение) |
| `scripts/ai_warehouse.py` | Аналитическая база: все данные программы в одном SQLite, словарь данных |
| `scripts/ai_eval.py` | Контрольные вопросы: проверка качества ответов на живой модели |

Настройки: `OLLAMA_HOST` (по умолчанию `http://localhost:11434`), `OLLAMA_MODEL` (по умолчанию `qwen3:4b`).
Модель можно сменить в интерфейсе; список — `GET /api/tags`. **Нужна модель с поддержкой инструментов** (`tools`
в `ollama show`): `check_ollama_model` иначе отказывает с понятным текстом. Проверено на `qwen3.5:9b`.

```bash
.venv/bin/python scripts/ai_agent.py "Как дела в магазине?"   # задать вопрос из терминала, видны шаги и вызовы
```

## Подключение к Ollama

Каждый запрос (`_build_ollama_payload`) передаёт:

| Параметр | Переменная `.env` | По умолчанию | Зачем |
|---|---|---|---|
| `options.num_ctx` | `OLLAMA_NUM_CTX` | 32768 | Без него Ollama берёт 4096 токенов и **молча обрезает** начало запроса — системный промпт и данные инструментов. Сжатые данные трёх месяцев занимают ~7,6 тыс. токенов |
| `keep_alive` | `OLLAMA_KEEP_ALIVE` | `30m` | Модель не выгружается между вопросами |
| `think` | `OLLAMA_THINK` | не передаётся | `1`/`0` — включить/выключить размышления; передаётся, только если модель их поддерживает |
| таймаут чтения | `OLLAMA_READ_TIMEOUT` | 600 с | Большой контекст на ноутбуке читается минутами |

`chat` возвращает `ChatResponse`: текст, размышления, `tool_calls`, токены запроса и ответа, `error` (сеть, HTTP-ошибка
Ollama — исключений нет), `cancelled`. `context_overflow` — запрос занял ≥ 95 % окна и мог быть обрезан
(видно в Debug-журнале). Возможности модели — `POST /api/show`, кеш на модель.

Тесты — `tests/test_ai_transport.py`.

## Аналитическая база

`scripts/ai_warehouse.py` собирает **все** данные программы в один SQLite-файл `.cache/ai/warehouse.db`.
База производная: её можно удалить, следующий `refresh` соберёт её заново.

```bash
.venv/bin/python scripts/ai_warehouse.py   # собрать/обновить и показать таблицы, строки, диапазоны дат
```

| Источник (`SOURCES`) | Файлы | Таблицы |
|---|---|---|
| `ozon_reports` | `reports/Ozon/<Год>/<Месяц Год>.xlsx` | `ozon_orders`, `ozon_month_metrics` (блок P/Q), `ozon_other_expenses`, `ozon_ad_campaigns` |
| `wb_reports` | `reports/WB/<Год>/WB <Месяц Год>.xlsx`, лист «Данные» (в старых — «Заказы») | `wb_orders`, `wb_month_metrics` |
| `costs` | `costs.xlsx` | `products` (лист «Основной»), `product_promotions` (лист «Акции», одна строка — товар × акция) |
| `abc_xyz` | `ABC&XYZ reports/*.xlsx` | `abc_xyz` (лист «Итог» каждого отчёта, с `report_period`) |
| `supply` | `stocks reports/Поставка FBO <дата>.json` | `fbo_supply_plan` (артикул × зона), `fbs_needs` |
| `organic` | `analytics history/organic_last.json` | `organic_products` (диагностика и советы текстом), `organic_store` |
| `snapshots` | `analytics history/snapshots/*.json` | `product_snapshots` |
| `actions_log` | `actions history/auto_actions_log.jsonl` | `auto_actions_log` |
| `wb_costs` | `wb_costs.xlsx` | `wb_products` |
| `search` | `search data/search.db` (открывается только на чтение) | `search_products` (SKU ↔ артикул), `search_keywords`, `search_sku_keywords`, `search_query_stats`, `search_sku_daily`, `search_positions`, `search_card_snapshots` |

Не входят: финансовые JSON Wildberries (`wb reports/`), кэши заказов `stocks reports/.orders_cache/`,
баланс (`balance reports/`), настройки `*_settings.json`, данные из API без сохранения на диск.

Правила:
- **Словарь данных — `CATALOG`.** Таблица → описание, источник, колонки (тип SQLite и описание на русском),
  колонка даты. Из него создаётся схема и строится каталог для модели (`describe`: строки, диапазон дат,
  время загрузки, ошибка источника). Таблица без источника в `SOURCES` — ошибка (тест).
- Имена таблиц и колонок латиницей (модели проще писать SQL), описания — по-русски. Артикул везде текстом
  (`artikul`), месяц — `YYYY-MM` (`period`), даты — `YYYY-MM-DD`. Расходы — со знаком минус, как в отчётах.
- **Пересборка по источникам.** Подпись источника — список `(путь, mtime_ns, размер)` его файлов, хранится
  в `_sources`. Совпала — источник пропускается; нет — его таблицы очищаются и загружаются заново в одной транзакции.
  Удалённый файл меняет подпись, его строки исчезают.
- **Ошибка источника** (битый файл) не мешает остальным: таблицы источника остаются пустыми, текст ошибки —
  в `_sources.error` и в каталоге; подпись не сохраняется, поэтому следующая сборка попробует снова.
- `SCHEMA_VERSION` поднимайте при изменении `CATALOG`: база со старой версией удаляется и собирается заново.
- Сборка идёт под `file_lock.exclusive_file` на файл базы. `connect` открывает базу **только на чтение**
  (`mode=ro` + `PRAGMA query_only`).

Сверка с реальными данными: по всем 21 месяцу Ozon число строк, сумма прибыли, выручка и все показатели P/Q
совпадают с `load_monthly_report_detailed_data` / `load_report_summary`. Старые загрузчики дополнительно считают
пустые строки листа (январь 2025, WB июль 2026); в базе их нет.

Представления `VIEWS` (колонки — как у базовой таблицы) избавляют модель от выяснения, что самое свежее:
`abc_xyz_latest` (самый длинный отчёт среди закончившихся не раньше чем за 2 месяца до самого свежего — короткий
отчёт за 1–2 месяца для ABC ненадёжен), `product_snapshot_latest`, `fbo_supply_latest`, `fbs_needs_latest`.
`describe` показывает их с полем `view_of`.

Отправление из нескольких товаров месячный отчёт пишет одной строкой с артикулами через запятую («1101, 1105»);
суммы строки — по всему отправлению, поделить их между товарами нельзя. Такие строки остаются как есть
(итоги месяца сходятся), в разбивке по артикулам идут отдельной строкой; `find_products` разбирает их на артикулы.

Тесты — `tests/test_ai_warehouse.py`.

## Инструменты — `ai_tools.py`

`AnalyticsTools(root)` — инструменты для модели. **Всё, что можно посчитать, считает код (SQL)**: модель получает
готовые таблицы и объясняет их.

```bash
.venv/bin/python scripts/ai_tools.py store_overview '{"period": "2026-09"}'   # вызвать инструмент из терминала
```

| Инструмент | Что делает |
|---|---|
| `store_overview(period)` | Обзор месяца Ozon (по умолчанию — последний **полный**; идущий месяц — справкой в `facts`): итоги против прошлого месяца и года назад, лидеры/аутсайдеры по прибыли, рост и падение, критичные проблемы органики, нет остатка, нехватка на FBS, выручка WB |
| `month_metrics(period_from, period_to, metrics, marketplace)` | Официальные итоги месяцев (блок P/Q) таблицей показатель × месяц; по умолчанию 6 последних месяцев и ключевые показатели |
| `sales_metrics(period_from, period_to, group_by, artikuls, metrics, sort_by, order, limit, marketplace)` | Показатели по заказам с разбивкой по `period`, `artikul`, `scheme` (только Ozon), `status` |
| `product_table(months, abc, out_of_stock, below_min_price, artikuls, sort_by)` | Все товары одной таблицей: ABC/XYZ, остаток и индекс цен (последний снимок), цены, продажи и прибыль за N месяцев и за N месяцев до них, главная проблема, нехватка на FBS |
| `product_profile(artikul)` | Всё об артикуле: costs.xlsx, ABC/XYZ, продажи по месяцам за год, акции, анализ органики, снимки, план поставки, поиск, WB |
| `supply_needs(artikuls)` | Что пополнить по последнему плану: везти на FBO по зонам, нехватка на FBS, деньги по себестоимости |
| `find_products(query)` | Поиск артикула по фрагменту названия или артикула (Ozon, WB, costs.xlsx) |
| `calculate(expressions)` | Калькулятор (`ast`, без `eval`): числа, `+ - * / // % **`, скобки, `round/abs/min/max/sum/sqrt`. Модель обязана считать разницы, доли и проценты им |
| `describe_data(table)` | Каталог базы (`ai_warehouse.describe`) или колонки одной таблицы |
| `run_sql(sql, limit)` | Свой запрос по базе |
| `live_prices`, `live_stocks`, `live_promotions`, `live_discount_requests` | Текущие данные Ozon из API, **только чтение** |

Определения показателей `sales_metrics` повторяют месячный отчёт (`Monthly_sales_report.py`):
`revenue` — сумма цен продажи доставленных и возвращённых заказов («Общая выручка»); `profit` — сумма прибыли строк,
то есть **до** рекламы, хранения и расходов вне заказов (чистая прибыль месяца — только в `month_metrics`);
`avg_price` — средняя цена доставленных; `commission`, `logistics` — суммы по модулю. Для WB продажа — статус «продажа».

Правила:
- Результат инструмента — словарь `title`, `tables` ({имя: {columns, rows}}), `facts`, `notes` или `error` + `hint`.
  Ошибка инструмента (в том числе исключение) — ответ модели, ассистент не падает. `render` превращает результат
  в компактный текст: таблицы `| a | b |`, числа округлены до 2 знаков.
- Если последний месяц ещё идёт, в `notes` предупреждение: сравнивать его с полными месяцами напрямую нельзя.
- База пересобирается не чаще раза в 30 с (`REFRESH_INTERVAL_SECONDS`): один вопрос — несколько вызовов.
- `run_sql`: только `SELECT`/`WITH`, один оператор, соединение только для чтения, авторизатор SQLite разрешает
  только чтение, таймаут 10 с, по умолчанию 200 строк (максимум 1000). Ошибка SQL возвращается с подсказкой —
  модель может исправить запрос.
- Живые инструменты: ключи берутся `recommended_prices.refresh_api_credentials()`; без ключей — ошибка
  «Ключи Ozon не настроены». Результат кешируется на 5 минут (`LIVE_CACHE_SECONDS`) по инструменту и аргументам.
  По умолчанию берутся все артикулы `costs.xlsx`: `live_prices` — `organic_analysis.load_prices`
  (по 100 за запрос) плюс минимальная цена из `costs.xlsx` и цена для выгодного индекса
  (`price_for_good_index`) с выводом «снижать нельзя», если она ниже минимальной, `live_stocks` — один запрос `/v4/product/info/stocks` через `fbo_supply_plan.ozon_post`
  (свободно = в наличии минус резерв по типу склада), `live_promotions` — `get_actions_list`,
  `live_discount_requests` — `get_discount_requests` (артикул по SKU из базы поиска; имена и почта модераторов
  не передаются). Ни один инструмент ничего не меняет в Ozon.
- `TOOL_SCHEMAS` — описания для встроенного вызова инструментов Ollama; имена совпадают с методами (тест).

Проверка на `qwen3.5:9b` (контекст 32k): «что срочно пополнить и сколько денег» — 1 вызов `supply_needs`, 77 с;
«почему упали продажи 1102» — `product_profile` + `supply_needs`, 86 с; «товары класса A без остатка и их прибыль
за 3 месяца» — 1 вызов `product_table`, 55 с. Цифры в ответах совпали с данными.

Тесты — `tests/test_ai_tools.py`.

## Цикл ответа — `ai_agent.Agent`

Протокол — **встроенный вызов инструментов Ollama**: модель получает `tools=TOOL_SCHEMAS`, отвечает сообщением
с `tool_calls`; цикл добавляет это сообщение и по сообщению `{"role": "tool", "tool_name", "content": render(...)}`
на каждый вызов, затем снова спрашивает модель.

1. Сообщения: системный промпт (`SYSTEM_PROMPT`: дата, справка о данных `data_summary` — какие месяцы Ozon/WB есть
   и насколько свежи анализ, снимки, план, поиск; правила выбора инструментов, точности и формы ответа),
   последние `HISTORY_TURNS` = 3 пары «вопрос — ответ» (только текст; данные прошлых вопросов модель запрашивает
   заново), вопрос.
2. До `MAX_STEPS` = 8 запросов с инструментами, температура 0,3. Ответ стримится: размышления — в блок «Ход
   рассуждения», текст — в пузырь ответа. Если после текста пришли вызовы инструментов, текст сбрасывается
   (`answer_reset` → событие `ai_stream_reset`).
3. Повтор вызова с теми же аргументами не выполняется — модели возвращается «уже был выше».
4. На шаге `MAX_STEPS` после вызовов добавляется `FINAL_NUDGE`, следующий запрос — без инструментов.
5. Пустой ответ без вызовов — один повтор без инструментов с `EMPTY_NUDGE`; второй пустой — ошибка для пользователя.
6. **Бюджет контекста** (`_fit_context`): оценка `символы / 2,3` (замер на qwen3.5); окно `OLLAMA_NUM_CTX` минус
   `RESERVED_OUTPUT_TOKENS` = 6000 под размышления и ответ. Не влезает — самые старые результаты инструментов
   сжимаются до 1200 символов с пометкой. Один результат — не больше 35 % окна, иначе обрезается с советом сузить запрос.

Правила промпта, которые проверены на живой модели и важны для качества:
- цифры только из инструментов, любые вычисления — `calculate` (без него модель ошибалась в разнице и «во сколько раз»);
- текущий месяц не сравнивать с полными (иначе «выручка упала на 60%» по неполному октябрю);
- **никогда не советовать цену ниже минимальной** (без правила модель предлагала снизить 1102 до ~900 ₽ при минимальной 1277 ₽);
- при разборе товара смотреть все сигналы: остаток, индекс цен, акции, органика, отмены, поиск;
- ассистент ничего не меняет в Ozon и называет раздел программы для действия.

`app_flet.py` (`ai_submit`): один `AnalyticsTools` на сессию (живые данные кешируются между вопросами), на каждый
вопрос — новый `Agent` в `page.run_thread`. События агента → очередь интерфейса: `status` → `ai_stream_start`
(подпись под ответом), `thinking` → `ai_thinking_chunk`, `answer_chunk` → `ai_stream_chunk`, `tool` → лента шагов
и Debug-журнал, `model` → Debug-журнал. Отмена: `should_cancel` проверяется между шагами и во время стрима,
события отменённого запроса отбрасываются. Смена модели в списке заново проверяет её (`ai_refresh_status`).

Debug-режим (меню «Инструменты») пишет в журнал каждый ответ модели (токены, переполнение окна) и каждый вызов
инструмента с аргументами, временем и полным текстом результата. Журнал открывается по F2.

Тесты — `tests/test_ai_agent.py` (подставная модель по сценарию).

## Контрольные вопросы — `ai_eval.py`

Проверка качества ассистента на живой модели: вопросы с известным ответом. Запускайте после изменения промпта,
инструментов или смены модели и сравнивайте с прошлым отчётом.

```bash
.venv/bin/python scripts/ai_eval.py --list                 # вопросы и правильные ответы, без модели
.venv/bin/python scripts/ai_eval.py                        # все вопросы, несколько минут на каждый
.venv/bin/python scripts/ai_eval.py --case supply_money    # один вопрос
```

- Правильные ответы **не записаны вручную**: `build_cases` каждый раз считает их по базе (последний полный месяц,
  прошлый месяц, план поставки, класс A без остатка…). Если данных для вопроса нет, вопрос не задаётся.
- Проверки (`Check`): `number` — число есть в ответе с допуском 0,5 % (знак не важен: «−26 %» и «упала на 26 %»
  равны; «104 тыс.» вместо 103 989 — не засчитывается), `artikul`, `phrase`, `absent` (чего быть не должно).
  Плюс маршрут: хотя бы один из ожидаемых инструментов вызван.
- Балл вопроса — доля пройденных проверок (маршрут — одна из них); вопрос пройден, если пройдено всё.
- Отчёт с ответами, вызовами и временем — `.cache/ai/eval/<время>.json`.

| id | Что проверяет |
|---|---|
| `net_profit` | Официальные итоги месяца: выручка и чистая прибыль |
| `profit_change` | Процент изменения (через `calculate`, не в уме) |
| `cancels` | Число отмен и их доля |
| `top_profit` | Рейтинг товаров за 3 месяца |
| `supply_money` | Деньги на пополнение по плану поставки |
| `product_check` | Разбор одного товара (нехватка на FBS) |
| `abc_out_of_stock` | Сведение нескольких источников (ABC + остатки) |
| `ozon_vs_wb` | Сравнение площадок и разница |
| `no_actions` | Просьба снизить цену ниже минимальной: ассистент не утверждает, что что-то изменил, и объясняет ограничение |

Тесты самой проверки (разбор чисел, баллы, сборка вопросов) — `tests/test_ai_eval.py`, без модели.

## Ограничения

- Скорость: на MacBook M3 / 16 ГБ с `qwen3.5:9b` ответ занимает 1–5 минут, из них большая часть — размышления
  модели. `OLLAMA_THINK=0` заметно ускоряет, но ответы на сложные вопросы становятся слабее.
- Небольшие модели читают широкие таблицы с ошибками (могут перепутать соседние колонки) — поэтому колонки
  результатов названы по-русски и однозначно.
- Отчётные данные — на дату последнего формирования отчёта; свежие цены, остатки и акции модель берёт через `live_*`.

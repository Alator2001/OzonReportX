# 10. Реклама «Оплата за клик»

Вкладка «Реклама». Код: `scripts/ads_cpc.py` (подбор ставок), `scripts/performance_api.py` (расход для месячного
отчёта, см. [04](04-monthly-report.md#6-реклама)). Нужны ключи Performance API (`OZON_PERF_CLIENT_ID`,
`OZON_PERF_API_KEY`), иначе `PerfClient()` бросает «Не заданы OZON_PERF_CLIENT_ID и OZON_PERF_API_KEY…».

## Клиент — `PerfClient`

- Токен — `performance_api.get_performance_token` (`/api/client/token`), заголовок `Authorization: Bearer …`.
- `call(method, path)`: при 429 до 9 попыток с паузой 5, 10, 15 … 30 секунд (Ozon формирует только один отчёт
  статистики одновременно), любой ответ ≥ 400 — `RuntimeError` с текстом Ozon.
- **Единицы.** Ставки и бюджеты кампаний в API — в **миллионных долях рубля** (`MICRO = 1_000_000`):
  `bid / MICRO`, отправка — `to_micro(rub)` с округлением до копейки. Конкурентная ставка (`/bids/competitive`) —
  тоже в миллионных. **Минимальная ставка** (`/api/client/min/sku`) приходит **в рублях** (`0.28`) — делить не нужно
  (проверено 22.10.2026).
- Статистика: `sku_statistics` — асинхронный отчёт (`POST /api/client/statistics/json` → опрос `/statistics/{uuid}`
  каждые 3 секунды до 3 минут → `/statistics/report`), не больше 10 кампаний за запрос.
  `campaign_totals` — не больше 62 дней за запрос, длинный период делится и складывается.

## Экран

1. Список кампаний «Оплата за клик» за период (`list_cpc_campaigns`, без общей блокировки): работающие и все,
   у которых в периоде были показы или расход; расход, показы, клики, CTR, CPC, ДРР, стоимость заказа.
2. План ставок по работающим кампаниям или одной выбранной (`build_ads_plan`, под `job_lock`).
3. Отправка отмеченных изменений (`execute_ads_plan`, под `job_lock`).

## Экономика товара

`load_unit_economics` читает из `costs.xlsx`: себестоимость, **«Ожидаемая чистая прибыль»** (прибыль с единицы до
рекламы) и «Цена с учётом акций и скидок». Колонки прибыли нет — ошибка «синхронизируйте цены на вкладке
«Цены и скидки»». Поэтому план ставок верен ровно настолько, насколько свежа синхронизация цен
([05](05-pricing.md)).

## Настройки — `ads_settings.json`

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `profit_share` | 0.4 | Какую долю прибыли с заказа можно отдать на рекламу |
| `lookback_days` | 21 | Период статистики для решения |
| `include_model_orders` | true | Считать покупки соседних вариантов карточки после клика заказами товара |

## Решение по товару — `analyze_item`

Шаги с цифрами, как их проходит маркетолог. Первый «стоп» завершает разбор:

1. **Экономика.** Нет прибыли или себестоимости → `info` (ставку не трогаем). Прибыль ≤ 0 → `remove`
   (убрать товар из кампании: любая реклама только увеличит убыток). Иначе допустимая реклама на заказ
   = прибыль × `profit_share`, допустимый ДРР = маржа × `profit_share`.
2. **Наличие.** Свободного остатка (FBO + FBS) нет → `info`: Ozon сам не показывает рекламу, ставку не меняем.
3. **Стадия.** Меньше 150 кликов и меньше 28 дней в кампании — «тест»: за отсутствие заказов не наказываем,
   снижаем не больше чем на 10% за раз.
4. **Воронка** против средних по кампании (`campaign_benchmarks`): CTR при ≥ 300 показах, корзина при ≥ 40 кликах,
   покупка из корзины при ≥ 8 корзинах; слабо — ниже 60% от среднего. Если чаще покупают соседний вариант,
   слабая корзина не считается проблемой карточки.
5. **Окупаемость.** Реклама на заказ против допустимой; рекламный ДРР и общий (с органикой). Если общая выручка
   товара ≥ 2× рекламной — «много органики», снижаем осторожнее.
6. **Ставка** (только в стратегии «Средняя стоимость клика», `TARGET_BIDS`; в других стратегиях ставками управляет
   Ozon → `info`):

```
конверсия    = (заказы + 60·конверсия_кампании) / (клики + 60)     # smoothed_cr, сглаживание к кампании
безубыточная = конверсия × прибыль                                  # при ней реклама съедает всю прибыль
цель         = безубыточная × profit_share
```

- Много кликов без заказов (ожидалось ≥ 2 заказов, а их 0, не тест) → цель не выше половины текущей ставки.
- Шаг ограничен ±25% за раз (−10% в тесте и при большой органике), снизу — минимальная ставка Ozon.
- Изменение меньше `max(0,10 ₽, 3% ставки)` не предлагаем → `keep`.
- Если конкурентная ставка Ozon в 1,5 раза выше безубыточной — предупреждение, что рекламой товар выгодно
  не разогнать.

Конверсия кампании: заказы / клики, если у кампании ≥ 100 кликов и есть заказы; иначе общая по всем кампаниям;
если и её нет — 2% (`FALLBACK_CR`).

Итоговые действия: `bid_down`, `bid_up`, `remove` (отмечены по умолчанию), `keep`, `info`.

## Рекомендации по кампании — `campaign_advice`

- Окупаемость: доля расхода от прибыли с рекламных заказов против `profit_share`.
- Бюджет: темп расхода недельного бюджета с начала рекламной недели (`startWeekDay` кампании). Если бюджет
  кончится раньше и реклама окупается — совет поднять его на 20%.
- Сезон (`season_outlook`): продажи магазина в следующие 30 дней год назад к предыдущим 30 по кэшу заказов
  плана поставки (`stocks reports/.orders_cache`). Рост в 1,3 раза и больше — совет готовиться заранее,
  падение до 75% и ниже — совет снижать расходы. Нет кэша — блока нет.
- Структура: тестовые и зрелые товары в одной кампании — совет разделить.

## Отправка — `execute_ads_plan`

По кампаниям: `PUT /api/client/campaign/{id}/products` с новыми ставками, `POST .../products/delete` для `remove`.
Затем перечитывает товары кампании и засчитывает изменение, только если ставка совпала с целевой с точностью
до 1,5 копейки (или товар исчез из кампании). Подтверждённые изменения пишутся в журнал
`ads reports/changes.jsonl`.

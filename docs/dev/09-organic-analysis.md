# 09. Анализ органических продаж

Вкладка «Анализ». Код: `scripts/organic_analysis.py`, запуск — `run_analysis(ROOT, days, progress)` в потоке
**под `job_lock`** и только по кнопке «Начать анализ» (при открытии вкладки и смене периода ничего не загружается,
показывается прошлый результат из `analytics history/organic_last.json`).

Задача: объяснить по каждому товару, почему он продаётся или не продаётся **без рекламы**.

## Периоды — `analysis_periods(today, days)`

Длина периода — 7, 14, 28 (по умолчанию, ровно 4 недели) или 56 дней. Все отрезки полуоткрытые `[начало, конец)`:

| Ключ | Отрезок |
|---|---|
| `current` | последние `days` дней по вчерашний день включительно |
| `previous` | такой же отрезок перед ним |
| `current_ly`, `previous_ly` | те же отрезки **364 дня назад** — 52 недели, чтобы совпадали дни недели |

**Сезонная норма** (`season_expectation`): как менялись продажи магазина между `previous_ly` и `current_ly`.
Считается, только если в `previous_ly` было не меньше 10 штук.

## Источники данных

`run_analysis` собирает всё сам; каждый источник, кроме заказов и `costs.xlsx`, обёрнут в `safe(...)`:
при ошибке анализ продолжается без него, а в списке источников результата появляется строка со статусом `bad`
и текстом ошибки.

| Источник | Функция | Откуда |
|---|---|---|
| Заказы FBO+FBS без отмен, ~24 месяца | `fbo_supply_plan.load_orders` | Seller API, кэш по месяцам ([08](08-fbo-supply.md)) |
| Артикулы и минимальные цены | `load_costs_df` | `costs.xlsx` (без файла анализ падает) |
| Реклама по SKU за оба периода и рекламные заказы по неделям | `load_ads` | Performance API через `ads_cpc.PerfClient` (без ключей — источник `bad`) |
| Свободный остаток | `ads_cpc.load_available_stock` | `/v4/product/info/stocks` |
| Цена, индекс цен, акции | `load_prices` | `/v5/product/info/prices` |
| Средняя цена продажи по периодам | `load_price_history` | месячные отчёты `reports/*.xlsx` (лист «Заказы», без отмен) |
| Контент-рейтинг и что добавить | `load_content_rating` | `/v1/product/rating-by-sku` |
| Доставка из кластера покупателя | `load_locality` | `/v1/analytics/local-sale/items-clusters/info` |
| Поиск: позиции, «увидели», запросы | `load_search` | `/v1/analytics/product-queries` (+ `/details`). Без Premium — пусто или 403 |

**Органика = все заказы товара − заказы, которые Ozon приписал рекламе** (рекламные заказы не больше общих).

## Снимки — своя история

Ozon не отдаёт историю цен, остатков, индекса цен и рейтинга. Программа копит её сама:
`analytics history/snapshots/<ГГГГ-ММ-ДД>.json` — по одному файлу в день, на артикул: цена, остаток,
цвет индекса, число акций, контент-рейтинг.

- Пишется при каждом анализе и **после каждой синхронизации цен** (`snapshot_after_sync`, вызывается из
  `ui_actions.py refresh-pricing`). Синхронизация рейтинг не загружает и берёт его из сегодняшнего снимка,
  если он уже есть.
- `snapshot_events` показывает, что менялось перед падением: цена на ≥ 5%, закончился / появился остаток,
  смена индекса цен, число акций, рейтинг на ≥ 5 пунктов.

## Диагностика товара — `analyze_product(p, store)`

Чистая функция без сети: на входе собранные числа, на выходе шаги со статусами (`bad`, `warn`, `info`, `ok`),
главная проблема и рекомендации. Её проверяет `tests/test_organic_analysis.py`.

| Шаг | Что смотрим | Когда плохо |
|---|---|---|
| Продажи | заказы и органика к прошлому периоду, сезонная норма | органика упала на 30% хуже сезона (`warn`), на 50% (`bad`); нет продаж вообще; без рекламы не продаётся |
| Наличие и доставка | остаток, дней с последнего заказа, доля доставок из кластера покупателя | остатка нет (`bad`); из своего кластера < 30% при ≥ 3 доставках (`warn`) |
| Цена | средняя цена к прошлому периоду, индекс цен, участие в акциях | цена выросла на ≥ 10% при падении органики; индекс «умеренный» (`warn`) / «невыгодный» (`bad`) |
| Карточка | контент-рейтинг | < 90 — `warn`, < 70 — `bad` |
| Воронка | CTR, корзина, заказ по рекламному трафику против средних по магазину | показатель < 60% от среднего (нужно ≥ 100 показов; для корзины ≥ 30 кликов, для заказа ≥ 8 корзин) |
| Реклама | доля рекламных заказов | ≥ 70% при ≥ 3 заказах |
| Поиск | позиции и запросы (Premium) | средняя позиция > 50 |

**Индекс цен** (`parse_price_index`): у Ozon три сравнения — с продавцами на Ozon, с конкурентами вне Ozon
и с вашим же товаром на других площадках. Худший (наибольший индекс) определяет, кто дешевле.
Если минимальная цена конкурентов вне Ozon совпадает с вашей на другой площадке (разница < 1 ₽), виновником
считается ваш же товар. Цена для индекса около 1,00 — `текущая цена / индекс` (`price_for_good_index`). Это
ориентир: Ozon считает индекс по цене для покупателя. Если она ниже вашей минимальной цены, программа прямо
пишет, что конкурировать ценой невыгодно.

**Приоритет.** Каждая рекомендация получает вес (например, нет остатка — 1000, невыгодный индекс — 400,
подъём по доставке — 300) плюс «потерянные» органические заказы × 10. Главная проблема — шаг самой весомой
рекомендации. Товары сортируются по приоритету, затем по числу заказов. Товары без заказов в обоих периодах,
без рекламы и без остатка в результат не попадают.

## Результат

`analytics history/organic_last.json`: период, магазин в целом (заказы, органика, рекламные заказы,
сезонная норма, воронки рекламы и поиска, есть ли Premium), недельный график (все заказы и рекламные за 12 недель),
товары с шагами и рекомендациями, список источников со статусами.

## Нюансы

- На уровне магазина рекламные заказы считаются как `orders + models` (заказы других моделей той же карточки),
  а на уровне товара — только `orders`. Поэтому сумма органики по товарам может не совпасть с органикой магазина.
- Дата заказа — дата принятия в обработку (`in_process_at`), а не отгрузки; рекламная статистика — по дням Ozon.
- Без Performance API органика = все заказы: шаг «Воронка» становится информационным («мало рекламного трафика»),
  а «Реклама» показывает 0% рекламных заказов — это не значит, что рекламы нет, а значит, что её не загрузили
  (смотрите источник «Реклама» в списке источников).
- Средняя цена продажи берётся из месячных отчётов: если отчёта за месяц нет, цена этого месяца не учитывается.

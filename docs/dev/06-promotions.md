# 06. Акции Ozon

Раздел «Акции» в приложении. Код: `scripts/price_management.py` (календарь, планы, исполнение),
`scripts/recommended_prices.py` (запросы к Ozon, бустинг, цена в акции), автоакции — [07](07-auto-actions.md).

> **Изменения в акциях меняют цену товара в реальном магазине.** Перед правками прочитайте раздел
> «Единая цена» целиком.

## Единая цена (с 19 октября 2026)

Ozon перевёл акции на «единую цену» (unified price logic) и заблокировал старые методы
`v1/actions/products`, `v1/actions/candidates`, `v1/actions/products/activate`, `v1/actions/products/deactivate`
(ответ `400 {"code": 9, "message": "the method is blocked due to unified price logic..."}`).

Что изменилось по существу (выводы из документации и данных магазина, проверено 22.10.2026):

- **Цена в акции — это цена продавца** (та же, что «Текущая цена на Ozon» и минимальная/желательная цена
  в `costs.xlsx`), а не цена на витрине. Покупатель видит её за вычетом скидок Ozon (обычно на 30–35% ниже).
- **Пока акция идёт, цена товара равна цене в акции.** У всех участников «Эластичного бустинга»
  (бессрочная акция) `action_price == price` карточки. Для акций, которые ещё не начались (11.11),
  цена в акции задана отдельно от текущей. По всей видимости, она станет ценой товара с начала акции.
- **Добавить в акцию / изменить цену в акции** — `POST /v1/actions/products/update`
  (в описании метода: до переключения он «не мог изменить цену на карточке» — значит, теперь может).
- **Удалить из «Эластичного» и «Максимального бустинга» отдельной командой нельзя.** `v2/actions/products/deactivate`
  работает только для акций «Промокоды», для бустингов отвечает code 9. По документации, товар выводится из
  акции, когда его цена в акции **не ниже лимита акции**. В данных магазина товары с ценой, равной
  `max_action_price`, в акции остаются, поэтому программа ставит **лимит + 1 ₽**.
- Одна цена у товара на все акции: выход из одной акции по меньшей цене может вернуть товар в другую.

Проверено в боевом режиме 22.10.2026: «Удалить невыгодные» (цена «лимит + 1 ₽») выводит товар из акции.
Не проверено: момент, когда меняется цена на карточке, в том числе для акций, которые ещё не начались
(см. [99](99-known-issues.md)).

## Данные акции

`get_actions_list()` — `GET /v1/actions`, все доступные акции магазина. `describe_action(raw)` превращает
их в `{id, name, action_type, fixed_boost, date_end}`:
- `action_type`: `ELASTIC_BOOSTING` (эластичный бустинг) или, например, `STOCK_DISCOUNT` (так приходят
  «Максимальный бустинг» и его «усиление»);
- `fixed_boost` — бустинг акции с фиксированным бустингом. Отдельного поля у Ozon нет, поэтому он
  **вытаскивается регуляркой из HTML-описания** акции («бустинг … — 55%», `parse_fixed_boost`).
  Изменение текста описания Ozon может сломать распознавание — тогда бустинг будет `None`.

Товары акции — `fetch_action_products(action_id, "products" | "candidates")` через `fetch_action_page`
(`/v2/actions/...`, `limit=100`, пагинация `last_id`). `normalize_action_product` переводит все денежные
поля `{amount, currency}` в `float` и запоминает `currency`. Важные поля:

| Поле | Смысл |
|---|---|
| `id` | `product_id` (не SKU и не артикул). Артикул — через `get_product_id_mapping` (`/v5/product/info/prices`) |
| `price` | цена товара (продавца) |
| `action_price` | цена в акции; у кандидата 0 |
| `max_action_price` | максимальная цена, при которой товар может участвовать, — **лимит акции** |
| `add_mode` | `AUTO` — добавил Ozon (автодобавление), `SELLER` — продавец |
| `current_boost` | текущий бустинг товара, % (бывает 0 — тогда считаем сами) |
| `min_boost`, `max_boost`, `price_min_elastic`, `price_max_elastic` | шкала эластичного бустинга |
| `stock`, `min_stock` | для «Скидки на сток» |

Ошибка страницы в `fetch_action_products` печатается в лог, и функция возвращает то, что успела загрузить
(не исключение) — см. [99](99-known-issues.md).

## Бустинг

`boost_at_price(action_info, product, price)` (`recommended_prices.py:500`):
- **эластичный**: линейно от `min_boost` при цене `price_min_elastic` до `max_boost` при `price_max_elastic`
  (чем ниже цена, тем выше бустинг); выше `price_min_elastic` — минимальный, ниже `price_max_elastic` — максимальный;
- **остальные** — фиксированный бустинг из описания акции.

`_current_boost` — сначала `current_boost` от Ozon, если он ненулевой, иначе расчёт по цене.
`_boost_fields` — диапазон бустинга акции и цена максимального бустинга (для подсказки в интерфейсе).

## Календарь акций

`load_actions_calendar(repo_root)` (`price_management.py:731`), загружается при первом входе на вкладку
(без общей блокировки). Для каждой акции: даты по Москве (`_moscow_date` — UTC + 3 часа), тип, бустинг,
даты автодобавления Ozon (`auto_add_dates`), дата заморозки, сколько товаров ещё можно добавить и список
участников с ценой, скидкой от цены и бустингом. Участники грузятся параллельно (до 6 потоков), с одним
повтором при сбое (Ozon иногда держит запрос дольше 30 секунд); ошибка одной акции показывается в её карточке.

## Планы действий

Все планы строятся **без отправки** в Ozon, показываются пользователю списком с галочками и отправляются
только по кнопке «Отправить в Ozon». Общая подготовка — `_load_plan_context`: лимиты цен из `costs.xlsx`
(минимальная и желательная), акции, маппинг `product_id → артикул`. Учитываются только товары из `costs.xlsx`.

Видимость в поиске за 14 дней (`_attach_visibility` → `get_search_visibility`) добавляется к позициям
для справки. Без Premium позиции и просмотры пустые.

### «Удалить невыгодные» — `build_action_removal_plan`

Загружает участников всех акций параллельно (до 4 потоков), включая акции, которые ещё не начались.
В план попадает участник, у которого цена в акции **ниже минимальной цены**:

| Ситуация | Позиция |
|---|---|
| Акция позволяет цену не ниже минимальной (`pick_action_price` по лимиту акции) | `raise` — поднять цену, товар остаётся в акции и сохраняет бустинг |
| Лимит акции ниже минимальной цены или неизвестен | `remove` — вывести ценой выхода (ниже) |

Цена подъёма — `pick_action_price(минимальная, желательная, лимит)`, но не выше общей цены товара
(`_plan_entry_prices`, все акции, где товар участвует, обязательные): подъём не выбрасывает товар из других акций.
Желательная берётся из `costs.xlsx`, если есть, иначе минимальная. Подъём отмечен, в `note` пояснение.

Цена выхода:

```
цена выхода = max(минимальная цена, floor(max_action_price) + 1, текущая цена товара)     # action_exit_price
```

Текущая цена товара — поле `price` участника акции. Для идущей акции она равна цене в акции (ниже минимальной)
и на результат не влияет. Для акции, которая ещё не началась, товар уже продаётся дороже лимита: тогда цена
выхода равна текущей, и вывод не меняет цену товара. Пример (артикул 1302, 22.10.2026): Ozon сам добавил
товар в «Максимальный бустинг: усиление 11.11» (начало 28.10) по 936 ₽ при лимите 936 ₽, минимальная 945 ₽,
товар продаётся по 978 ₽ — цена выхода 978 ₽, а не 945 ₽.

Позиция плана хранит `product_price` (текущая цена товара), `action_start` (дата начала по Москве, если акция
ещё не началась), `added_by_ozon` (`add_mode == "AUTO"`) и `note`. Приложение пишет «С 28.10 цена в акции
станет 936 ₽ — ниже минимальной 945 ₽ · для выхода цена товара останется 978 ₽» и отдельной строкой — что акция
ещё не началась и что товар добавил Ozon. Дата начала берётся из `date_start` акции (`describe_action`).

Потом `_unify_plan_prices` (см. «Одна цена на товар в плане»): если товар выводится из нескольких акций,
всем его позициям ставится наибольшая цена выхода; если товару в другой акции поднимается цена, а вывод требует
цены выше, подъём снимается с отметки. Позиция без лимита акции (Ozon не прислал `max_action_price`)
не отмечается и не отправляется.

Почему не желательная цена: она обычно намного выше минимальной (в магазине — в 2,3 раза). При единой цене
это стало бы ценой товара, и продажи, скорее всего, встали бы.

### «Добавить выгодные» — `build_action_add_plan`

Загружает кандидатов и участников всех акций параллельно (до 4 потоков). Акция, где цены не ниже минимальной
нет (`pick_action_price` = None), пропускается. Цена товара одна на весь план — `_plan_entry_prices`
(см. «Выбор общей цены» ниже).

- **Кандидат** → `add` (отмечен). Если ради этой акции общую цену пришлось бы заметно снизить — `add`
  без отметки, с `costly: True`, ценой, которая станет у товара во всех акциях, и пояснением в `note`.
- **Участник** → `raise` до общей цены, только если его цена не ниже минимальной (ниже — это задача удаления) и подъём
  заметный: не меньше `max(10 ₽, 1% цены)` (`RAISE_MIN_STEP_*`). Подъём, который снижает бустинг,
  по умолчанию **не отмечен** — решает пользователь (маржа или показы).
- **Кандидат, для которого цены не ниже минимальной нет** → `watch` (`_auto_add_watch`), только если впереди
  дата автодобавления акции (`auto_add_dates` ≥ сегодня по Москве) и минимальная цена в Ozon
  (`min_seller_price`) не выше лимита акции — тогда Ozon сам добавит товар по невыгодной цене. Это
  **предупреждение**: без галочки, никогда не отправляется (`execute_action_plan` берёт только
  `add`/`raise`/`remove`). В позиции — даты, лимит и `ozon_min_price`; приложение советует отправить свои
  минимальные цены в Ozon («Цены и скидки» → «Обновить минимальные цены в Ozon»), чтобы Ozon перестал добавлять
  товар дешевле них. Автодобавление не выключается: раньше кнопка «Порядок в предстоящих» выключала его
  у товара во всех акциях, а причина обычно в заниженной минимальной цене в Ozon (у артикула 1302 — 850 ₽ в Ozon
  против 945 ₽ в `costs.xlsx`).

### Убранная кнопка «Порядок в предстоящих»

До 22.10.2026 была отдельная кнопка для акций, которые ещё не начались. Вывод и добавление в такие акции уже
делали две основные кнопки (они проверяют все акции), поэтому её полезные части перенесены: подъём цены вместо
вывода — в «Удалить невыгодные», предупреждение об автодобавлении — в «Добавить выгодные».

### Выбор общей цены — `_plan_entry_prices`

У товара одна цена на все акции, поэтому участие в акции с низким лимитом снижает цену и во всех остальных.
Для каждого товара:

1. **Обязательные акции** — где товар уже участвует и остаётся (в «Добавить выгодные» — участники с ценой
   не ниже минимальной, в «Удалить невыгодные» — все участники, кроме выводимых). Цена не выше наименьшего их лимита:
   иначе товар выпадет оттуда.
2. **Необязательные** — куда товар только добавляется. Перебираются от высокого лимита к низкому: акция входит
   в общую цену, если снижает её не больше `max(10 ₽, 1%)` (тот же порог, что для подъёма, `RAISE_MIN_STEP_*`).
   Иначе она попадает в `costly` — в плане без отметки с текстом «участие снизит цену товара во всех акциях
   с X до Y ₽».
3. Цена — `pick_action_price(минимальная, желательная, наименьший учтённый лимит)`.

Пример: лимиты 1180 и 1050 ₽, желательная 1200 ₽. Товар идёт в первую акцию по 1180 ₽, вторая — без отметки
(−130 ₽). Если пользователь её отметит, при отправке цена товара станет 1050 ₽ во всех акциях.

### Одна цена на товар в плане — `_unify_plan_prices`

Ozon держит одну цену товара (и одну предельную цену) для цен и всех акций. Если отправить товару разные цены
в разные акции, они перезапишут друг друга, а сверка после отправки покажет «не применилось». Поэтому
перед показом плана и ещё раз перед отправкой (по отмеченным позициям) цены выравниваются по товару:

- `add` и `raise` — наименьшая из целевых цен **отмеченных** позиций товара (не выше лимита каждой из этих
  акций); у неотмеченных остаётся своя цена — та, что станет у товара, если их отметить;
- `remove` — наибольшая из цен выхода; если тот же товар в плане добавляется в другую акцию по цене
  не ниже неё, вывод идёт этой ценой — цена товара меняется один раз;
- если цена добавления ниже цены выхода (добавление вернуло бы товар в акцию, из которой он выводится),
  `add`/`raise` снимаются с отметки с пометкой `conflict` и пояснением в `note`. Если пользователь всё же
  отметит такую позицию, `execute_action_plan` её не отправит и покажет в ошибках.

При обычных данных такого конфликта почти не бывает: вывод нужен, только когда лимит акции ниже минимальной
цены, а подъём всегда не ниже минимальной. Исключение — вывод по текущей цене товара, которая выше цены подъёма. Правило — защита от ручной отметки и
от планов, собранных из разных данных.

Цены считаются только от `costs.xlsx` (минимальная и желательная), а не от текущей или предельной цены Ozon,
поэтому повторный запуск плана не снижает цену по спирали.

## Исполнение — `execute_action_plan(plan, mode)`

Берёт отмеченные позиции видов `add`/`raise`/`remove` (`watch` — никогда), выравнивает цены по товару
(`_unify_plan_prices`) и отправляет через `_send_plan_items` сначала выводы, затем добавления и подъёмы
(по акциям). `mode` влияет только на текст итога.

- вывод: `activate_products_in_action(action_id, [{product_id, action_price: exit_price}])`. Позиции без цены
  выхода попадают в ошибки;
- добавление и подъём: `{product_id, action_price, stock}`.

`activate_products_in_action` (`recommended_prices.py:794`) → `POST /v1/actions/products/update`
пачками до 1000: `action_price` как `{"amount": "1459.00", "currency": "RUB"}`, `stock` — только если > 0
(для бустингов Ozon просит его не передавать). Из ответа: `active_product_ids` и `deactivated_product_ids`
(строки → int), `rejected` с причиной, `warnings` печатаются в лог.

**Проверка по факту.** После отправки план заново загружает участников акции и засчитывает позицию, только если:
- `remove` — товара в акции больше нет;
- `add`/`raise` — товар в акции и его цена отличается от целевой меньше чем на 0,5 ₽.

Итог: «Удалено из акций: N из M (проверено по данным Ozon)», плюс «Ozon отклонил» (с причиной Ozon, например
«Product update has no changes») и «Не применилось без объяснения». Если в «Удалить невыгодные» есть подъёмы,
итог называется «Применено в акциях».

После успешной отправки приложение запускает синхронизацию цен (`ui_actions.py refresh-pricing`),
чтобы обновить лист «Акции» и цены в `costs.xlsx`, и перезагружает календарь.

## Блокировки

Сборка плана и отправка берут `job_lock` (одновременно с другой задачей нельзя); загрузка календаря — нет.

## Удаление «Промокодов» и старый путь

`deactivate_products_in_action` (`v2/actions/products/deactivate`, `product_ids` строками) остаётся для акций
«Промокоды». На code 9 он не падает, а возвращает понятную ошибку («Ozon перевёл акции на единую цену…»).
Сейчас его не вызывает ни один сценарий: планы выводят товары ценой.

При расчёте рекомендованных цен (`recommended_prices.run`) товары с ценой в акции ниже минимальной больше
**не выводятся** автоматически — печатается только сообщение со ссылкой на кнопку «Удалить невыгодные».
Добавление кандидатов там тоже отключено: печатается, сколько позиций можно добавить, со ссылкой на кнопку
«Добавить выгодные».

## Проверка новой логики без последствий

- Отправить через `update` ту же цену, что уже стоит: Ozon вернёт `rejected: "Product update has no changes"`,
  ничего не изменится, зато видно, что метод принимает запрос.
- Вызвать удаление для товара, который в акции не участвует (кандидата).
- Собрать план (`build_*_plan`) без отправки и посмотреть цены — сборка ничего не отправляет.

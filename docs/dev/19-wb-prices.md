# 19. Цены и акции Wildberries (исследование)

Раздела цен и акций для WB в приложении **пока нет**. Здесь записано, как WB устроен на самом деле: методы API
и разбор живых данных магазина. Это основа для задач будущего раздела (список задач — в конце).

Проверено 27.10.2026: документация dev.wildberries.ru и запросы к API **только на чтение** (`/api/v2/list/goods/filter`,
`/api/v2/quarantine/goods`, календарь акций) с токеном из `.env`, плюс финансовые отчёты `wb reports/2026-04…10.json`
(126 строк «Продажа»). В кабинете ничего не менялось.

## Цепочка цены

```
цена продавца (price)                4000 ₽   ← задаёт продавец
− скидка продавца (discount)          −64 %   ← задаёт продавец (и автоакции WB, см. ниже)
= цена со скидкой продавца            1440 ₽   ← от неё считаются деньги продавца
− скидка WB (СПП, spp)             −30,28 %   ← задаёт WB, персонально для покупателя
= заплатил покупатель (retailAmount)  1004 ₽
```

Реальная продажа артикула 1205, октябрь 2026.

### Выплата продавцу

На всех 126 продажах в отчётах без единого расхождения (допуск 1,5 ₽):

```
forPay = retailPriceWithDisc × (1 − commissionPercent / 100) − acquiringFee
```

Для 1205: 1440 × (1 − 0,38) − 40,16 = 852,64 ₽ — как в отчёте.

- **СПП оплачивает WB из своей комиссии.** Во всех 126 строках `kvw = kvwBase − spp` ровно: базовая комиссия
  31,15 %, фактически WB берёт 0,87 %. Продавец СПП не задаёт и не платит. Она меняет только цену для покупателя,
  то есть спрос.
- **Эквайринг** (`acquiringFee`) — около 4 % от `retailAmount` (суммы, которую заплатил покупатель), разброс в данных 0,4–4,9 %.
- В финансовом отчёте `retailPrice` = `retailPriceWithDisc` = цена **уже со скидкой продавца**, `salePercent` = 0
  во всех продажах. Исходную цену и скидку продавца в отчёте не видно — только в API цен.
- **Комиссия выросла:** апрель 2026 — около 20 %, июнь — 29,5–32 %, август–октябрь — 38–41,5 %. Причина не установлена
  (смена модели продаж или тарифа?) — проверить в кабинете, это главный фактор маржи.
- Средняя СПП по месяцам: 18–40 % (максимум в строке — 45,5 %). Цену для покупателя можно только оценить.

**Отличие от Ozon** ([06](06-promotions.md)): на Ozon с 19.10.2026 «единая цена» — цена в акции и есть цена товара.
На WB у товара две величины — цена и скидка %, и акции работают через скидку.

## API цен — `discounts-prices-api.wildberries.ru`

Токен категории «Цены и скидки». Лимит на все методы категории: 10 запросов за 6 секунд (интервал 600 мс, всплеск 5).

| Метод | Что делает |
|---|---|
| `GET /api/v2/list/goods/filter` | Все товары: `limit=1000`, `offset` += `limit`, пока не придёт пустой массив. `filterNmID` — один артикул |
| `POST /api/v2/list/goods/filter` | То же по списку `nmList` |
| `GET /api/v2/list/goods/size/nm` | Размеры одного товара (только при `editableSizePrice: true`) |
| `GET /api/v2/quarantine/goods` | Товары в карантине: `newPrice`/`oldPrice`, `newDiscount`/`oldDiscount`, `priceDiff` |
| `POST /api/v2/upload/task` | Установить `price` и/или `discount` по `nmID`, до 1000 товаров |
| `POST /api/v2/upload/task/size` | Цены по размерам (`sizeID`), до 1000. Карантин к ним не применяется |
| `POST /api/v2/upload/task/club-discount` | Скидка WB Клуба `clubDiscount`, % |
| `POST /api/discounts-prices/v1/upload/task/b2b/wholesale` | Оптовые скидки B2B по уровням |
| `GET /api/v2/history/tasks`, `/history/goods/task` | Статус и ошибки обработанной загрузки по `uploadID` |
| `GET /api/v2/buffer/tasks`, `/buffer/goods/task` | Загрузки, ждущие старта акции (статус `1`) |

Ответ чтения по товару: `nmID`, `vendorCode`, `discount`, `clubDiscount`, `editableSizePrice`,
`wholesaleDiscountThreshold`, `sizes[]` — `sizeID` (= `chrtID` в Контенте), `price`, `discountedPrice`, `clubDiscountedPrice`.

**Запись асинхронная:** ответ — `uploadID` (и `alreadyExists` для дубля). Статусы загрузки: `3` — всё применилось,
`4` — отменена, `5` — часть товаров с ошибками, `6` — ошибки во всех. Статуса `2` не бывает. Применившееся
нужно проверять по факту, как в соглашениях для Ozon.

### Карантин цен

Если новая цена со скидкой ниже порога, товар продаётся по старой цене, пока продавец не подтвердит изменение
в кабинете (или не поменяет цену через API). В детализации загрузки ошибка `New price is several times lower than
the current price. Item has been moved to Price Quarantine`. По сторонним новостям 2026 года порог настраивается по
категориям примерно от 33,3 до 47,5 % снижения (раньше было «в 3 раза») — сверить в кабинете. Следствие: резко
уронить цену одним шагом программа не сможет.

### Данные магазина (27.10.2026)

- 49 товаров, у всех один размер и `editableSizePrice: false`, `clubDiscount` = 0, оптовых скидок нет, карантин пуст.
- Скидки продавца от 0 до 71 %: у многих товаров завышенная цена при большой скидке (например, 4000 ₽ − 64 %).

## Календарь акций — `dp-calendar-api.wildberries.ru`

Токен категории «Цены и скидки». Лимит: 10 запросов за 6 секунд.

| Метод | Что делает |
|---|---|
| `GET /api/v1/calendar/promotions` | Акции за период: `startDateTime`, `endDateTime` (`YYYY-MM-DDTHH:MM:SSZ`), `allPromo` (`true` — все, `false` — доступные). Поля `id`, `name`, даты, `type`: `regular` / `auto` |
| `GET /api/v1/calendar/promotions/details` | По `promotionIDs`: описание, преимущества, счётчики участия, `participationPercentage`, `exceptionProductsCount` (только auto), `ranging` |
| `GET /api/v1/calendar/promotions/nomenclatures` | Товары акции: `price`, `planPrice`, `discount`, `planDiscount`, `inAction`. **Не работает для автоакций** |
| `POST /api/v1/calendar/promotions/upload` | Добавить товары в акцию (`uploadNow`: сразу или в момент старта). **Не работает для автоакций** |

`ranging` — ступени буста в поиске: `condition` (`productsInPromotion` и др.), `participationRate` — доля ассортимента
для ступени, %, `boost` — буст, %.

### Автоакции

1. WB сам рассчитывает, какие товары и с какой скидкой войдут в акцию.
2. **На старте WB сам меняет скидку продавца**, и товар становится участником. Пример: артикул 1218 в октябре
   продавался по 1204 ₽ (2800 ₽ − 57 %), 27.10 стоит 1036 ₽ (− 63 %).
3. За участие — буст в поиске («11.11»: +30 %, при участии больше 50 % рассчитанного ассортимента — +35 %), плашка,
   баннер, «градусник» остатков.
4. До старта товары можно исключить или задать минимальную цену — **только в кабинете**, методов API для этого нет.
   После старта выйти можно, только подняв цену выше плановой: если текущая цена равна плановой цене автоакции или ниже, товар
   всё равно в неё попадёт.

**Ограничение API:** по автоакциям доступны только счётчики. `nomenclatures` на автоакцию отвечает
`422 Unprocessable entity` (проверено для 3053, `inAction` true и false). Какой товар в какой автоакции и по какой
цене — из API не узнать, только косвенно: по изменению скидки в таблице цен.

### Данные магазина (27.10.2026)

21 акция за период −30…+60 дней, **все `auto`**: «Бархатные скидки», «Большая распродажа», «Осенние скидки»,
«11.11» и их подакции. Участие — примерно половина ассортимента с остатком: «11.11» — 17 из 35, «Осенние скидки»
(3053) — 15 из 32, «11.11: хиты» — 0 из 4. Исключённых товаров (`exceptionProductsCount`) нет.

## Раздел «Цены» в приложении (сделано 27.10.2026)

Пункт меню WB «Цены» (`scripts/wb_prices_view.py`, расчёт — `scripts/wb_prices.py`), в том же виде, что «Цены и
скидки» Ozon, но только для чтения: заявок на скидку у WB нет, кнопки «Рассчитать цены» нет — минимальная и
желательная цена считаются при каждом показе.

- **«Синхронизировать»** (и сама при входе, не чаще раза в 5 минут) — `wb_prices.sync`: цены и скидки, предметы
  товаров, тарифы комиссии → снимок `wb reports/prices.json` (с `account = sha256(токена)`).
- **Таблица** — `wb_prices.compute` по снимку, финансовым отчётам последних 3 загруженных месяцев и `wb_costs.xlsx`.
  Подсветка как у Ozon: цена со скидкой красная ниже минимальной, зелёная от минимальной, тёмно-зелёная от желательной;
  рентабельность красная ниже минимальной маржи, зелёная до желаемой; отрицательная прибыль — красная.
- **Комиссия** — фактическая доля по продажам артикула, иначе серии, иначе тариф WB по предмету (бо́льший из FBS
  и FBW), иначе средняя по магазину. Тариф раньше средней магазина: продажи магазина — почти одни доски (38–41,5%),
  а у икон и оберегов комиссия ниже (20–33%).
- **Маржа WB** — свои настройки `wb_price_settings.json` (по умолчанию 25% и 30%), не общие с Ozon.
- **«Можно ставить скидку»** — диапазон скидки продавца при текущей цене до скидки: от скидки для желательной цены
  (`discount_desired`) до скидки для минимальной (`discount_max`), `wb_prices.discount_for`: наибольшая целая скидка,
  при которой цена со скидкой не ниже цели (WB принимает только целые проценты, округление вниз). Текущая скидка
  подсвечена: больше допустимой — красная, в диапазоне — зелёная, не больше «желательной» — тёмно-зелёная. Если даже
  без скидки цена ниже минимальной — «поднять цену до скидки».

## Раздел «Акции» в приложении (этап 1, сделан 27.10.2026)

Пункт меню WB «Акции» (`scripts/wb_promotions_view.py`, расчёт — `scripts/wb_promotions.py`), только чтение.
«Синхронизировать» (и сама при входе, не чаще раза в 5 минут): снимок цен (`wb_prices.sync`) и
`wb_promotions.sync` — календарь акций с подробностями и скидки в заказах за 30 дней → `wb reports/promotions.json`.

- **Буст и пороги** (`tiers`): буст получают все участники акции, уровень — по доле ваших товаров с остатком
  (`ranging`: `participationRate` → `boost`). «До следующего уровня» — наименьшее число товаров, после добавления
  которых доля ≥ порога. 27.10.2026 после вывода 4 товаров из «11.11» участие упало 17 → 13 из 35 (49 → 37%),
  и буст всем участникам — 30 → 25%.
- **Цена в акции** (`promo_discount`): API не отдаёт товары автоакций, поэтому скидка акции — наибольшая скидка
  артикула за 30 дней по истории скидок (`wb reports/price_history.json`, `record_history` при каждой синхронизации
  цен, только изменения) и скидкам в заказах (статистика WB, `discountPercent`). Скидка сейчас ниже — «вышел из
  акции»; равна — «по истории не видно». В историю вручную добавлены цены WB на 27.10.2026 22:07:19 (до ручного
  повышения) для 1116, 1117, 1118, 1119, 1217, 1219.
- **Окупаемость** (`multiplier`): прибыль на минимальной цене / прибыль в акции — во сколько раз буст должен поднять
  продажи. Вердикт: цена акции не ниже минимума — «конфликта нет»; прибыль в акции ≤ 0 — «выйти: убыток»;
  ×1,5 и меньше — «держать», до ×3 — «смотреть по продажам», больше — «выйти: буст не окупится».
- **«Что делать»** (`advice`) — вердикт с учётом статуса: вердикт отвечает, стоит ли товару быть в акции, а совет —
  что делать сейчас. Вышел из акции и вердикт «выйти» — «не возвращать» (зелёный, всё правильно); вышел, а буст
  окупается — «вернуть в акцию» (жёлтый); в акции и «выйти» — «… — поднять цену» (красный). Колонка «По факту» —
  так же. Сортировка: сначала нужно действие, потом решить, потом всё правильно.
- **Этап 2 — факт** (сделан 27.10.2026): статистика карточек по дням (`/api/analytics/v3/sales-funnel/products/history`:
  только последняя неделя, до 20 товаров в запросе, 3 запроса в минуту; больше — только с подпиской «Джем»)
  копится в `wb reports/daily_stats.json` при каждой синхронизации (`load_daily_funnel`, `merge_daily`). День
  относится к «со скидкой акции», если скидка в этот день (`discount_on`: история скидок, иначе заказ в этот день,
  иначе самая ранняя запись истории — оценка) не меньше скидки акции артикула. `daily_effect` — переходы и заказы
  в день с каждой стороны; переходы — замена продаж (заказов 1–5 на артикул в месяц, по ним не сравнить). Вердикт
  «по факту» (`fact_verdict`): от 3 дней с каждой стороны — рост переходов против нужного роста продаж. По сериям
  (`series_rows`, 11xx, 12xx, …) — то же суммарно. Не сделано: загрузка выгрузки товаров акции из кабинета.
- Этап 3 — подсказка оптимальной скидки по сериям, когда накопится история.

## Задачи раздела (черновик)

От простого к сложному. Пункты 1–4 только читают данные.

1. **Таблица цен WB.** По каждому nmId: цена, скидка, цена со скидкой, себестоимость из `wb_costs.xlsx`, фактическая
   комиссия и логистика за единицу по последним отчётам. Из них выплата, прибыль и маржа по формуле выше и
   оценка цены для покупателя со средней СПП.
2. **Минимальная и желательная цена WB** — как для Ozon ([05](05-pricing.md)), от себестоимости, маржи и комиссии WB.
   Решить: свои настройки маржи для WB или общие.
3. **Календарь акций:** даты, тип, участие в %, ступени буста, сколько дней до старта; пометка, что исключать товары
   можно только в кабинете.
4. **Отслеживание автоакций:** ежедневный снимок таблицы цен и разница скидок («1218: 57 → 63 %, маржа …»);
   подсветка товаров, у которых цена ушла ниже минимальной.
5. **Изменение цен из приложения.** Цена и скидка, проверка статуса загрузки, разбор ошибок и карантина,
   чтение результата по факту. **Нужен токен с правом записи** в категории «Цены и скидки» — текущий только читает.
6. Позже: скидка WB Клуба; выяснить рост комиссии с ~20 % до ~38 %.

Открытые вопросы:
- Комиссия 20 % → 38–41,5 %: откуда рост и сохранится ли он.
- Порог карантина для категорий магазина.
- Где брать комиссию для расчёта на будущее: из последних отчётов или из тарифов WB (метод тарифов по комиссии
  не проверялся).

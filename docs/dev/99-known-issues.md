Список собран при написании документации (22 октября 2026): проверка кода и запросы к API Ozon.
Пункты отсортированы по влиянию. Исправленный пункт удаляйте из списка вместе с коммитом исправления.

Исправлено 22 октября 2026: запуск приложения без ключей Ozon (`balance_report` больше не завершает процесс при импорте), зависание кнопки «Проверить обновления» (добавлена кнопка «Установить обновление»), поиск артикула через удалённый `/v2/product/info`.

## Ошибки

### 1. `/v1/warehouse/fbo/list` требует `filter_by_supply_type` (400)
`recommended_prices.get_fbo_warehouse_ids` (`recommended_prices.py:2128`) отправляет только `search`,
Ozon отвечает 400, ошибка глотается, возвращается пустое множество. Из-за этого
`get_fbo_stocks_by_offer_ids` всегда возвращает пустой результат (остатки FBO = 0).
Функцию вызывает только `scripts/fbo_supply_report.py`, а он нигде не запускается (устаревший модуль),
поэтому на работу программы это сейчас не влияет. Если модуль будет нужен — исправить запрос или удалить код.

### 2. Ошибка списка акций выглядит как «акций нет»
`recommended_prices.get_actions_list` (`recommended_prices.py:253`) при любой ошибке запроса возвращает `[]`.
Планы акций показывают «Активные акции не найдены», календарь — пустой список. Пользователь не узнает,
что Ozon просто не ответил. То же у `fetch_action_products`: ошибка страницы печатается в лог,
а план собирается по неполным данным.

## Риски, требующие решения

### 3. Автоматическое добавление в акции при расчёте рекомендованных цен
При запуске `recommended_prices.py` напрямую (консольное меню «Цены и скидки → Рассчитать рекомендованные цены»,
`run(..., include_actions=True)`, блок «Проверка кандидатов для добавления в акции») программа без подтверждения
добавляет кандидатов в акции по цене между минимальной и желательной. Приложение этот путь не использует:
кнопка «Рассчитать» вызывает `ui_actions.py recommended-prices`, а там `include_actions=False`.
При «единой цене» Ozon добавление в акцию, по всей видимости, задаёт цену товара. Вывод из акций
в этом сценарии уже отключён (только сообщение) — решение по добавлению за владельцем продукта.

### 4. Вывод из бустинга ценой выше лимита не проверен в боевом режиме
Правило «цена выхода = max(минимальная, лимит акции + 1 ₽)» основано на документации Ozon
(«измените `action_price` на значение больше или равное лимиту акции») и на наблюдении, что
товары с ценой, равной `max_action_price`, остаются в акции. Реальный вывод ещё не отправлялся.
Неизвестно, меняется ли при этом цена на карточке сразу, в том числе для акций, которые ещё не начались.

### 5. Обработка заявок на скидку идёт без общей блокировки
Одобрение и отклонение заявок (`process_discount_request_item`, `process_discount_request_plan`)
отправляют решения в Ozon в потоке без `job_lock` и могут выполняться одновременно с другой задачей.
Конфликта данных нет (заявки не пересекаются с другими операциями), но это расходится с правилом
«изменения в Ozon — под общей блокировкой».

## Ограничения расчётов

### 6. Поздние начисления теряются
Месячный отчёт учитывает начисления по отправлениям месяца, пришедшие не позже 21 дня после конца месяца
(`ACCRUAL_LOOKAHEAD_DAYS`). Возврат, оформленный позже, не попадёт ни в один отчёт, пока отчёт за тот
месяц не сформируют заново. Подробно — [04](04-monthly-report.md#нюансы-и-подводные-камни).

### 7. Границы месяца в UTC
Заказы и начисления отбираются по UTC; первые три часа месяца по Москве относятся к предыдущему месяцу.

### XYZ: ровный спрос получает «Недостаточно данных»
`ABC_XYZ_analytics_report.py`: коэффициент вариации 0 всегда превращается в «Недостаточно данных». Так бывает
и при одном месяце продаж (верно), и при одинаковом числе заказов каждый месяц (должно быть X). Отличить можно
по числу месяцев с продажами. Подробно — [11](11-abc-xyz.md#нюансы).

### План запасов WB использует метод статистики, названный устаревшим
`wb_supply_plan.load_recent_orders` берёт заказы через `statistics-api.wildberries.ru/api/v1/supplier/orders`,
а `wb_orders.py` прямо пишет, что Order Feed заменил «устаревшие методы статистики заказов и продаж».
Не проверялось; если WB отключит метод, план запасов перестанет считаться. Кроме того, метод вызывается одним
запросом без пагинации.

## Обслуживание

### 8. Перенос данных забирает не всё
`scripts/transfer_data.py` не переносит `fbo_supply_settings.json`, `wb_supply_settings.json`,
`ads_settings.json`, журнал автоакций `actions history/`, журнал ставок `ads reports/`,
историю анализа `analytics history/`. После переноса настройки поставок и рекламы вернутся к значениям
по умолчанию, а журнал «Ozon включил автодобавление обратно» начнётся заново.

### 9. Мелочи автообновления
- `CURRENT_VERSION = "1.0.0"` в `_auto_update.py` — запасное значение, если нет `version.txt`.
- Временная папка жёстко задана как `~/AppData/Local/Temp/ozonreportx_update` (только Windows).
- Список `preserve` не содержит `fbo_supply_settings.json`, `wb_supply_settings.json`, `ads_settings.json`,
  `actions history`, `analytics history`, `ads reports`. Сейчас это безопасно: файлов нет в zipball
  релиза (они в `.gitignore`), и обновление их не трогает.

### 10. Устаревший код
- `scripts/fbo_supply_report.py` — старый расчёт поставок по ABC/XYZ, нигде не вызывается.
- В `Monthly_sales_report.to_excel` комментарий «ключ может быть точным offer_id или префиксом»
  не соответствует коду: сопоставление себестоимости точное.

### 11. Разные механизмы повторов
У каждого модуля свой способ повторять запросы при 429/5xx (см. [03](03-ozon-api.md#где-берутся-заголовки)),
а `organic_analysis._post` не повторяет вовсе. Единый клиент Seller API упростил бы сопровождение.

### 12. Обратный перевод цветов темы неоднозначен
`themed_color` переводит тёмную тему обратно в светлую инверсией таблицы, а несколько светлых цветов
переходят в один тёмный. Подробно — [02](02-app-architecture.md#тема).

# 02. Архитектура приложения

Приложение — один файл `app_flet.py` на [Flet](https://flet.dev) (`flet 0.84`, Python-обёртка над Flutter).
Почти весь код находится внутри функции `main(page)` (`app_flet.py:1272`, ~6,9 тыс. строк):
элементы интерфейса, состояние и обработчики — замыкания внутри неё. На уровне модуля лежат
только чистые функции: форматирование чисел, чтение `costs.xlsx` и отчётов, валидация полей,
переиспользуемые карточки (`card`, `metric`, `hero_metric`), `stream_process`.

## Запуск и инициализация

1. Импорт `app_flet.py`. Модули с бизнес-логикой импортируются в блоках `try/except`:
   если модуль не загрузился, вместо функций кладутся `None`, а текст ошибки — в `*_IMPORT_ERROR`
   (`AI_IMPORT_ERROR`, `PRICING_IMPORT_ERROR`, `ADS_IMPORT_ERROR`, `ORGANIC_IMPORT_ERROR`).
   Раздел с недоступным модулем показывает эту ошибку, остальные работают.
   **Исключение:** `balance_report`, `file_io`, `file_lock`, `ui_log`, `wb_dashboard`, `abc_view`,
   `marketplace_settings` импортируются без защиты — их сбой не даёт приложению запуститься.
   Поэтому в этих модулях нельзя ничего проверять при импорте (ключи, файлы, сеть): только при вызове.
2. `ft.run(main)` → `main(page)` строит все разделы сразу (не лениво), добавляет разметку
   и заставку (`splash_overlay`).
3. Через `page.run_task` запускаются две корутины:
   - `ui_event_loop` — бесконечный цикл обработки очереди событий (см. ниже);
   - `initialize_app` — первое чтение данных с диска (`refresh_dashboard`, `refresh_files`,
     `refresh_pricing_costs_preview`, отрисовка разделов), скрытие заставки и, если
     `needs_setup(ROOT)`, открытие мастера подключения.

`PYTHON` (`app_flet.py:124`) — интерпретатор для дочерних процессов: `.venv/Scripts/python.exe`,
если он есть, иначе `python` из `PATH`.

## Разметка и навигация

- Слева `sidebar`: переключатель магазина и темы (`top_tools_shell`), меню разделов (`rail`),
  блок статуса задачи (`status_shell`) с кнопкой «Отмена».
- Справа `host` — колонка, в которую подставляется текущий раздел. Список разделов —
  `views = [dash, ai_view, reports, pricing, actions, ads_view, analysis_view, search_view_section, supply, stock_view, settings, file_view]`
  (`app_flet.py:7731`), подписи — `section_names`.
- `show_store_section(index)` (`app_flet.py:7786`) меняет содержимое `host`, перерисовывает
  раздел и **запускает автоматические загрузки при входе**:

| Вход в раздел | Что запускается | Идёт через очередь задач |
|---|---|---|
| «Цены и скидки» | загрузка заявок на скидку, затем синхронизация цен `ui_actions.py refresh-pricing` — не чаще раза в 5 минут и только если нет другой задачи и несохранённых правок (`auto_sync_pricing`) | синхронизация — да, заявки — нет |
| «Акции» (первый вход) | `calendar_load()` — календарь акций; `auto_load()` — автоакции | нет |
| «Реклама», «Анализ» | только перерисовка, загрузок нет | — |
| «Поиск» (первый вход) | `search_load()` — чтение `search data/search.db` через `search_view.load()`, без сети | нет |

- **Магазин Wildberries.** `active_store` переключает Ozon/WB. Для WB `wb_section(index)` возвращает
  свои экраны: сводку `wb_dashboard` (собирается в `scripts/wb_dashboard.py`), план запасов
  и настройки. Для остальных разделов показывается заглушка «Раздел Wildberries готовится».

## Фоновые задачи

Сетевые операции и тяжёлые расчёты не выполняются в потоке интерфейса. Есть два механизма.

### 1. Задача-процесс: `job(title, cmd)`

`app_flet.py:3793`. Используется для всего, что реализовано скриптом в `scripts/`:
месячный отчёт, ABC/XYZ, план поставки FBO/WB, баланс, синхронизация цен, расчёт рекомендованных
цен, отправка минимальных цен, проверка обновлений.

```
job(title, cmd)
 ├─ job_lock.acquire(blocking=False)  — занято → toast «Дождитесь завершения текущей операции»
 ├─ статус «Выполняется: <title>», лог очищается командой
 └─ page.run_thread(worker)
      └─ stream_process(cmd, on_line, on_prompt, extra_env, proc_holder=active_proc, cancel_event)
           ├─ каждая строка stdout → ui_queue ("log_append", line)
           └─ по завершении → ui_queue ("finish", title, code, output)
finish(title, code, output)  — в потоке интерфейса
 ├─ освобождает job_lock, снимает флаги синхронизации
 ├─ перечитывает данные с диска: refresh_dashboard, refresh_pricing_costs_preview, refresh_files
 └─ выполняет отложенное действие (построить график, открыть ABC/XYZ), если задача успешна
```

`stream_process` (`app_flet.py:215`):
- запускает процесс с `cwd=ROOT`, `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8`, `PYTHONUNBUFFERED=1`;
  stdout и stderr объединены, stdin — канал;
- хранит последние 500 строк вывода — их и возвращает как `output` (в журнал сессии пишется всё);
- **протокол вопросов**: если в строке встречается «введите сумму затрат на продвижение ozon»
  или «введите сумму затрат на внешний маркетинг», вызывает `on_prompt(label, line)` и пишет ответ
  в stdin процесса. Других вопросов интерфейс не понимает — скрипт, который ждёт `input()`
  с другим текстом, будет ждать до отмены;
- в `finally` гарантированно убивает процесс и закрывает каналы.

Все задачи-процессы взаимоисключающие: одновременно выполняется не больше одной (`job_lock`).

### 2. Задача-поток: `page.run_thread(worker)` с вызовом Python-функции

Для операций, которым нужен структурированный результат (план с галочками, данные для таблицы),
приложение вызывает функции модулей напрямую в потоке: планы акций (`build_action_*_plan`,
`execute_action_plan`), автоакции (`auto_actions.load_state`, `apply_change`), реклама
(`build_ads_plan`, `execute_ads_plan`, `list_cpc_campaigns`), календарь акций (`load_actions_calendar`),
заявки на скидку, анализ (`organic_run_analysis`), AI-ассистент.

Поток **не может трогать элементы интерфейса напрямую** — он кладёт событие `("call", функция)`
в `ui_queue`, и функция выполняется в цикле событий. Исключение — `set_status`/`toast`, которые
вызываются из потоков и сами вызывают `page.update` (Flet это допускает).

Блокировка у задач-потоков разная:

| Операция | Берёт `job_lock` |
|---|---|
| Сборка и отправка плана акций, отправка автоакций, сборка и отправка плана рекламы, анализ, сохранение таблицы `costs.xlsx`, подготовка недостающих отчётов для графика | да |
| Календарь акций, загрузка автоакций, список кампаний рекламы, загрузка **и обработка** заявок на скидку, AI | нет |

Операции без блокировки могут выполняться **одновременно** с задачей-процессом и делить
с ней лимит запросов Ozon (см. [03](03-ozon-api.md#лимиты)). Все они, кроме обработки заявок
на скидку, только читают данные. Обработка заявок отправляет решения в Ozon без общей блокировки
(см. [99](99-known-issues.md)).

## Очередь событий `ui_queue`

`ui_queue` (`app_flet.py:2362`) — `queue.Queue`, единственный безопасный способ из фонового потока
что-то изменить в интерфейсе. `ui_event_loop` (`app_flet.py:4487`) выбирает все события за проход
и спит 10 мс (если были события) или 30 мс.

| Событие | Действие |
|---|---|
| `("log", text)` / `("log_append", text)` | заменить / дополнить лог |
| `("finish", title, code, output)` | завершение задачи-процесса → `finish(...)` |
| `("run_job", title, cmd)` | запустить задачу-процесс из потока (например, синхронизация цен после изменения акций) |
| `("call", fn)` | выполнить `fn()` в потоке интерфейса |
| `("prompt", label, source_line, holder, event)` | показать диалог ввода суммы маркетинга (см. ниже) |
| `("ads_rebuild",)` | пересобрать план рекламы |
| `("ai_step" / "ai_stream_start" / "ai_thinking_chunk" / "ai_stream_chunk" / "ai_stream_reset" / "ai_finish", …)` | потоковый вывод AI-ассистента ([14](14-ai-assistant.md#цикл-ответа--ai_agentagent)) |

### Вопрос пользователю из дочернего процесса

`request_prompt(label, source_line)` (`app_flet.py:2460`) выполняется в рабочем потоке
`stream_process`: кладёт в очередь событие `prompt` с `holder` (словарь для ответа)
и `threading.Event`, затем ждёт событие с проверкой отмены каждые 100 мс. Диалог в интерфейсе
пишет ответ в `holder["value"]` и выставляет событие. При отмене возвращается `"0"`.
Период для заголовка диалога угадывается по тексту строки или по выбранному месяцу
(`infer_prompt_period`).

## Отмена

`cancel_current_action` (`app_flet.py:2308`):
1. Если идёт AI-запрос — помечает его отменённым (ответ модели будет отброшен), задачу не трогает.
2. Иначе выставляет `cancel_state["requested"]` и `job_cancel_event`, закрывает открытый диалог
   вопроса (ответ `"0"`).
3. Если есть дочерний процесс — `kill_process_tree`: на Windows `taskkill /PID <pid> /T /F`
   (убивает всё дерево процессов), на macOS/Linux `SIGTERM` всей группе процессов. Для этого
   `stream_process` запускает дочерний процесс в своей сессии (`start_new_session=True`), и id группы
   совпадает с pid. Так останавливаются и вложенные скрипты (например, `Monthly_sales_report.py`,
   запущенный из `recommended_prices.py`), которые иначе продолжили бы работать и держать блокировку файла.

Задачи-потоки отмену не поддерживают: Python-функцию в потоке остановить нельзя, поэтому для них
статус показывается с `cancellable=False`. Отменённая задача-процесс завершается с кодом ≠ 0;
`finish` показывает «Отменено: <title>» и не выполняет отложенных действий.
Скрипты сами отвечают за то, чтобы прерывание не оставило полузаписанных файлов —
поэтому вся запись идёт атомарно (`file_io`).

## Журнал

- `SessionLog` (`scripts/ui_log.py`) пишет **полный** вывод сессии в `.cache/logs/ui-<время>-<uuid>.log`
  и держит в памяти последние 500 строк.
- В интерфейсе два представления: список строк `log` (последние 500) и поле `log_selectable`
  для копирования. Полный журнал открывается по F2 — только при включённом Debug-режиме
  в инструментах AI-ассистента.

## Статус

`set_status(title, detail, color, busy, cancellable)` — плашка внизу слева: заголовок, детали
(обрезаются до 140 символов), индикатор, крутилка и кнопка «Отмена» (видна при `busy and cancellable`
или пока жив дочерний процесс). `toast(msg, error)` дополнительно показывает всплывающее сообщение.

## Сворачивание бокового меню

Кнопка рядом с кнопкой темы (`sidebar_button` → `toggle_sidebar`) сворачивает левую колонку
с 264 до 92 px: `apply_sidebar_layout` переводит `rail` в режим только иконок (`extended=False`,
`label_type=NONE`, подписи разделов уходят в подсказки), прячет названия магазинов, текст статуса
(он показывается подсказкой на `status_shell`), заменяет «Инструменты» и «Отмена» иконками,
а верхние кнопки ставит столбиком. Состояние запоминается между запусками в `.cache/ui_state.json`
(`load_ui_state` / `save_ui_state`; повреждённый файл означает развёрнутое меню).

При добавлении элементов в боковую колонку проверяйте, что они помещаются в 92 px или прячутся
в `apply_sidebar_layout`.

## Тема

Приложение стартует в теме системы (macOS и Windows): `page.platform_brightness` → `system_prefers_dark`
→ `apply_theme(start_dark)`. Если Flet тему системы не сообщил, берётся тёмная. Пока пользователь не нажал
кнопку темы, `on_platform_brightness_change` переключает приложение вслед за системой. Нажатие кнопки
фиксирует выбранную тему до конца сессии (`follow_system_theme`); если выбранная тема совпадает
с системной, следование за системой включается снова. Выбор между запусками не сохраняется.

Цвета в коде пишутся **в светлой палитре**,
а при смене темы `apply_control_theme` (`app_flet.py:3118`) обходит дерево элементов и переводит цвета
через таблицу `themed_color` (`app_flet.py:1205`).

Что нужно знать при добавлении элементов:
- Цвет, которого нет в таблице `themed_color`, не меняется при смене темы.
- Обратный перевод (тёмная → светлая) строится инверсией таблицы. Несколько светлых цветов
  переходят в один тёмный (например, `#3A3A3C`, `#4A302E`), поэтому обратно они вернутся
  в один из исходных цветов, не обязательно в тот, что был.
- Контейнер с `data="preserve_excel_fill"` и текст с `data="preserve_excel_text"` не перекрашиваются.
  Ими помечены ячейки с заливкой из `costs.xlsx` и элементы, которые сами выбирают цвет
  по теме (`ads_palette()`, `analysis_colors()`).
- Цвета текста из наборов `PRIMARY_TEXT_COLORS` / `MUTED_TEXT_COLORS` заменяются на основной
  и приглушённый цвет текущей темы.

## Таблица `costs.xlsx` в интерфейсе

Раздел «Цены и скидки» показывает лист «Основной» как редактируемую таблицу:
- читается `read_costs_main_rows` (`app_flet.py:544`) вместе с заливкой ячеек
  (условное форматирование рентабельности переводится в цвета интерфейса);
- колонка «Бустинг в акциях» только для чтения — собирается с листа «Акции»;
- редактировать можно только «Артикул» и «Себестоимость» (`EDITABLE_COSTS_COLUMNS`);
- сохранение (`write_costs_main_rows`) идёт под `job_lock` и с проверкой `file_signature`:
  если файл изменился после открытия таблицы (например, его поправили в Excel), запись
  отменяется с сообщением «Файл costs.xlsx изменился после открытия таблицы»;
- при несохранённых правках обновление таблицы спрашивает подтверждение, а автоматическая
  синхронизация цен не запускается.

## Как добавить новую функцию

1. Логику — в модуль `scripts/` с функцией, которую можно вызвать и из CLI, и из приложения.
   Без побочных эффектов при импорте, ключи читать при вызове.
2. Если результат — файл: запуск через `job(title, [str(PYTHON), str(SCRIPTS / "x.py"), ...])`.
   Вывод печатать построчно (`print(..., flush=True)`): он идёт в лог интерфейса.
   Не использовать `input()` — интерфейс не сможет ответить (кроме протокола вопросов о маркетинге).
3. Если результат — данные для экрана: импорт в `try/except` вверху `app_flet.py`, вызов в
   `page.run_thread`, отрисовка через `ui_queue.put(("call", render))`. Если функция меняет данные
   в Ozon — взять `job_lock` и освободить его в `finally`.
4. Запись файлов — только через `file_io.atomic_output_path` / `save_workbook_atomic`.
5. Изменения в Ozon — только по подтверждению пользователя, с проверкой результата по свежим
   данным из Ozon после отправки.

# 12. Заявки покупателей на скидку

Диалог на вкладке «Цены и скидки». Код: `price_management.build_discount_request_plan`,
`process_discount_request_item`, `process_discount_request_plan`; запросы — `recommended_prices.get_discount_requests`,
`approve_discount_requests`, `decline_discount_requests`. Консоль: `ui_actions.py discount-requests`.

Покупатель может попросить скидку на товар; продавец одобряет (с ценой и количеством) или отклоняет.
Программа сравнивает запрошенную цену с «Минимальной ценой продажи» из `costs.xlsx`.

## Загрузка — `build_discount_request_plan(repo_root)`

1. Минимальные цены из `costs.xlsx` (только положительные). Нет ни одной — план с ошибкой.
2. Все заявки со статусом `NEW`: `POST /v2/actions/discounts-task/list`, страницы по 50 (`limit` у Ozon только
   из {5, 10, 15, 20, 30, 50}), следующая страница — по `id` последней заявки как `last_id`.
3. SKU заявок → артикул через `get_sku_to_offer_id_mapping`: сначала `/v3/product/info/list` по SKU, затем
   `get_product_info_by_id` (SKU как `product_id`), затем `/v5/product/info/prices`. Не нашёлся — артикулом
   считается сам SKU.
4. По каждой заявке — рекомендация:

| Условие | Рекомендация | Что готовится |
|---|---|---|
| В заявке нет SKU | отклонить | — |
| Нет минимальной цены для товара (нет в `costs.xlsx`) | **отклонить** | payload одобрения для ручного решения («товара нет в costs.xlsx») |
| Нет корректной запрошенной цены | отклонить | — |
| Запрошенная цена ≥ минимальной | одобрить | одобрение: `approved_price` = запрошенная (целое), количество от `requested_quantity_min` до `max` |
| Запрошенная цена < минимальной | отклонить | payload одобрения для ручного решения («ниже минимальной») |

Комментарий продавцу (`seller_comment`) формируется автоматически с цифрами.

## Обработка

- **По одной** (кнопки у заявки): `process_discount_request_item(item, "approve" | "decline")` — отправляет
  готовый payload. Одобрить можно и заявку с рекомендацией «отклонить», если у неё есть payload одобрения.
- **Автоматически** (кнопка «Обработать автоматически»): `build_discount_auto_plan` в приложении берёт текущий
  список и отправляет одобрения для рекомендованных к одобрению и **отклонения для всех остальных** —
  в том числе для товаров, которых нет в `costs.xlsx`. Перед этой кнопкой стоит убрать из списка заявки,
  которые хотите решить сами.
- Ответы `approve`/`decline` дают только общие счётчики успехов и ошибок. Если что-то не прошло, диалог
  требует обновить список перед повторной отправкой — иначе уже обработанные заявки ушли бы второй раз.

При входе на вкладку «Цены и скидки» заявки только **загружаются** (тихо, без сообщения «нет заявок»);
отправляет их только пользователь. Загрузка и обработка идут в потоке без общей блокировки задач
(см. [02](02-app-architecture.md), [99](99-known-issues.md)).

## Что сравнивается

`requested_price` в swagger описана как «Цена по заявке» — без уточнения, цена ли это продавца или цена для
покупателя. Программа сравнивает её с минимальной **ценой продавца** из `costs.xlsx`. В ответе есть и другие цены:
`original_price` («цена товара до всех скидок») и `min_auto_price` («минимальное значение цены после автоприменения
скидок и акций») — их программа не использует. Если окажется, что заявка в ценах покупателя, правило одобрения
нужно пересмотреть.

# 11. ABC/XYZ-анализ

Вкладка «ABC/XYZ-анализ». Код: `scripts/ABC_XYZ_analytics_report.py` (расчёт), `scripts/abc_view.py`
(чтение готового отчёта для экрана). Запуск из приложения:

```
ABC_XYZ_analytics_report.py -i reports --output_dir "ABC&XYZ reports" --from-month M --from-year Y --to-month M --to-year Y
```

Если месячных отчётов за выбранный диапазон не хватает, приложение сначала формирует их
(`build_missing_chart_reports`, см. [04](04-monthly-report.md)), затем запускает анализ.

Результат: `ABC&XYZ reports/<Месяц Год>-<Месяц Год>.xlsx` (диапазон берётся по именам найденных отчётов) с листами
«Итог» (первый, активный), «Заказы», «ABC», «XYZ» и «Отчёт» (если в каких-то файлах не нашлись колонки).

## Входные данные

- Файлы `reports/Ozon/**/*.xlsx|xlsm|xls` (включая папки по годам) с именем «Месяц Год», попадающие в диапазон (`parse_filename_to_month_year`).
  Без диапазона берутся все файлы папки.
- Только лист «Заказы» (или «Orders»), только строки со статусом **`delivered`**. Возвраты (`returned`),
  отмены, заказы в пути и «ожидает расчёта» не участвуют.
- Колонки ищутся по синонимам без учёта регистра и точек (`ALIASES`): «Артикул», «Цена продажи», «Количество шт.»,
  «Прибыль», «Дата отгрузки». Недостающие колонки — строка на листе «Отчёт».

## ABC — по прибыли

1. Сумма «Прибыли» по артикулу, сортировка по убыванию.
2. Доля в общей прибыли и накопительная доля.
3. **A** — накопительная доля ≤ 80%, **B** — ≤ 95%, **C** — остальное.

Убыточные артикулы уменьшают общую прибыль, поэтому накопительная доля у прибыльных может превысить 100% до того,
как дойдёт до убыточных, — все убыточные окажутся в C.

## XYZ — по стабильности спроса

1. Сводная таблица: артикул × месяц **по дате отгрузки**, значение — **количество строк-заказов** (`count`),
   а не штуки.
2. Регулярность: месяц с продажами, если заказов > 0. Порог — `round(число месяцев × 0,8)`.
   - **Нерегулярный спрос** (меньше порога): среднее, стандартное отклонение (по генеральной совокупности, `ddof=0`)
     и CV считаются **только по месяцам с заказами** (пустые месяцы — `NaN`, pandas их пропускает).
     X — CV ≤ 0,25, Y — ≤ 0,50, Z — выше.
   - **Сглаженный спрос** (не меньше порога): значения выше 2,5 медианы срезаются до 2,5 медианы (винзоризация,
     в таблице показаны в колонках «Винз. …»), месяцы ниже 0,3 медианы в среднее и отклонение не входят.
     X — CV ≤ 0,20, Y1 — ≤ 0,35, Y2 — ≤ 0,50, Y3 — выше.
3. CV = 0 → «Недостаточно данных».

## «Итог»

Склейка ABC и XYZ: «Общая оценка ABCXYZ» = буква ABC + класс XYZ (AX, AY1, …, CZ). Если XYZ — «Недостаточно
данных», то и общая оценка такая же. Сортировка: A → B → C, внутри X → Y1 → Y2 → Y3 → Z, «Недостаточно данных» в конце.
Под таблицей — легенда с интерпретацией и рекомендациями для каждой комбинации.

`abc_view.load_abc_report` читает «Итог», продажи по месяцам и CV для экрана приложения: матрица 3 × 3,
фильтры по клеткам, карточки артикулов.

## Нюансы

- **Месяцы — по дате отгрузки, а не по файлу.** Заказы из отчёта за сентябрь с отгрузкой в октябре дадут колонку
  «Октябрь» — число месяцев и порог регулярности вырастут.
- **Стабильный товар может получить «Недостаточно данных».** CV = 0 бывает и при одном месяце продаж, и при
  абсолютно ровном спросе (одинаковое число заказов каждый месяц). Во втором случае правильнее было бы X
  (см. [99](99-known-issues.md)).
- **Число заказов, а не штук.** Заказ на 5 штук и заказ на 1 штуку весят одинаково.
- **Прибыль из месячного отчёта.** Её точность зависит от того, как формировался отчёт ([04](04-monthly-report.md)):
  старые отчёты, сделанные по прежним правилам, нужно пересоздать.

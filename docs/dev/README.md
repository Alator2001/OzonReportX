# OzonReportX — документация для разработчиков

Эта документация описывает, **как программа устроена внутри**: какие модули за что отвечают,
как данные приходят из Ozon и Wildberries, как считаются показатели, какие файлы читаются
и пишутся и какие есть неочевидные места. Пользовательская инструкция — в корневом [README.md](../../README.md).

Документация сверена с кодом на момент написания (версия `3.5.0`, октябрь 2026).
Ссылки вида `scripts/Monthly_sales_report.py:440` ведут на конкретное место в коде;
при изменении кода номера строк могут сдвинуться — ищите по имени функции.

## Как читать

- Начните с [01](01-overview.md) и [02](02-app-architecture.md): почти все функции приложения
  устроены одинаково — интерфейс запускает скрипт из `scripts/` или функцию в фоновом потоке,
  а результат сохраняется в файлы в корне проекта.
- [03](03-ozon-api.md) нужен перед любой правкой запросов к Ozon: у Seller API жёсткие лимиты
  и он регулярно выводит методы из работы.
- Перед изменениями, которые отправляют что-то в Ozon (цены, акции, ставки рекламы),
  прочитайте соответствующий раздел целиком: такие операции меняют деньги в реальном магазине.

## Соглашения кода, которые стоит соблюдать

- **Неполные данные не сохраняются.** Если хотя бы одна страница ответа Ozon не загрузилась,
  функция бросает исключение, а не возвращает частичный список (см. `_get_postings`,
  `get_transactions_by_posting`). Отчёты пишутся атомарно через `scripts/file_io.py`.
- **Изменения в Ozon — только после подтверждения пользователя** и с проверкой по факту:
  после отправки программа заново читает состояние из Ozon и засчитывает только то,
  что действительно применилось (`execute_action_plan`, `auto_actions.apply_change`).
- **Тексты для пользователя — на русском**, комментарии в коде — по-русски или по-английски,
  как в окружающем коде.
- Тесты не ходят в сеть: все ответы API подменяются (`unittest.mock`). Запуск — см. [01](01-overview.md#тесты).
